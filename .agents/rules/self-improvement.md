# Self-Improvement & Continuous Learning Protocol

Whenever completing tasks in this repository, evaluate whether key learnings or operational friction should be captured:

1. **User Corrections & Insights:** Log to `.learnings/LEARNINGS.md` with category `correction`, `knowledge_gap`, or `best_practice`. Follow the decay-tracking ontology (`Decay-Type`, `Decay-Rate`, `Validation`, `Pattern-Key`).
2. **Command / Pipeline Failures:** Log unexpected runtime errors, test failures, or integration breakdowns to `.learnings/ERRORS.md`.
3. **Feature Requests:** Log requested missing capabilities to `.learnings/FEATURE_REQUESTS.md`.
4. **Promotion:** When a pattern recurs or represents an architectural invariant, promote it directly to `AGENTS.md` and/or `ARCHITECTURE.md` as per the repository law.
